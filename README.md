# 扫描件去黑边

清除扫描图片中的黑边、黑角、阴影条带和页边噪点，**保持原图尺寸与方向不变**，被清除的区域用周围纸张纹理修补，不留色块和分界线。

思路参考：
https://blog.gtwang.org/programming/python-opencv-auto-crop-and-rotate-scanned-image-tutorial/
https://blog.csdn.net/gitblog_00476/article/details/153671634

## 用法

```bash
uv run python pic.py 图片路径      # 处理单张
uv run python pic.py 图片目录/     # 处理目录下所有图片（不递归）
```

结果输出到 `output/`，文件名与原图相同。可选参数：`-t` 黑边灰度阈值（默认 80），`-m` 黑边向外多扩的像素（默认 4），`--no-enhance` 关闭淡字加深，`--no-interp` 关闭笔画恢复，`--text-method endpoint` 切回旧版端点连接，`--no-rotate` 关闭方向与倾斜校正，`--no-denoise` 关闭页边去噪，`-v` 输出详细日志。

## 处理思路

**先找出“不该出现在纸上的东西”，把它们标记出来，再根据周围的纸张把这些地方“补”回干净的样子。** 整个过程不裁剪、不旋转，所以图片尺寸和方向都不会变。

扫描件上常见的“脏东西”有四类，各用一种办法找：

0. **大面积的浅色彩色噪点（复印机的粉色墨粉斑、扫描仪的彩色竖条纹）**
   - 怎么找：不写死颜色，而是看每个像素“和纸张底色相比带多少颜色”（Lab 色度）。把浅淡的彩色像素按密度连成区域，**铺满大片、或贯穿页面一大段**的才算噪点，再取这些区域的主色相，只清这个色相附近的颜色，替换成纸张底色。
   - 怎么保护：颜色浓的（红头、红线、印章笔画）和颜色深的（哪怕本身是粉色，如粉色复印件上的字）连同紧贴的边缘都不动；彩色照片这种“大片但浓色多”的区域不动；不贴边、大致成圆的区域视为印章，整个保留，所以浅粉色的印章也不会被当成噪点。
   - 墨粉斑里偶尔有几颗颜色较深的小点，若很小且周围没有字和线，也一并清掉；挨着文字的标点不受影响。


**先保护骑缝章**：骑缝章压在页边、被图片边缘截断，颜色又常常很浅，最容易被下面的黑边、贴边笔迹步骤当成“脏东西”清掉。所以在清除之前先把它圈出来，之后所有步骤都不碰这块区域（修补时也不从章上取色，避免抹出一圈红晕）。用两条线索，任一条命中即保护：
   - 颜色（彩色扫描）：贴着图片边缘、有一定厚度和面积的带色块。黑边、直线旁扫描产生的 1~3 像素彩边太细，不算。
   - 残缺圆弧（黑白扫描）：在每条边的贴边条带里，对线状墨迹做 RANSAC 圆拟合，要求半径符合公章尺寸、圆被图片边缘截断、图内露出的圆弧够长且大部分被**连续**的墨迹覆盖、圆弧内外两侧都是空白（是一条孤立的线）。拟合前先去掉表格线、黑边带等长直线，免得直线和圆相切时冒充圆弧。命中后整个圆内都保护。
   - 章上若正好压着一段黑边，按章两侧的黑边厚度推算，只清掉紧贴边缘的那一条黑带。
   - 保护区只在原图上检测一次，之后随图像一起旋转、纠偏；纠偏始终保持原图尺寸：先整体平移，让转出画布的内容最少；剩下转出去的只能是本来就被图片边缘截断的墨迹（截断的字、扫描残迹、骑缝章）或零星墨点，否则不纠偏。

1. **黑边、黑角（贴着图片边缘的大块黑色）**
   - 怎么找：把足够黑的像素圈出来，只留下“和图片边缘连在一起”的那些。纸上的字再黑也不会连到图片边缘，（todo liang 但是要考虑边缘上真正的档案字体）。
   - 怎么扩：黑边旁边通常还有一圈发灰的过渡和过曝的白带，所以向外多扩一圈，一起处理掉，免得留下一条“边”。

2. **页边的“边框带”（颜色和纸不一样的窄条）**
   - 怎么找：有些扫描件边缘没有黑边，只有一条偏白、偏灰的窄带，或一条很淡的细线。办法是从图片边缘往里，一排一排地看像素的“典型亮度”（取中位数，不怕个别噪点），一直看到亮度和纸张正常亮度一致为止，这一段就是边框带。
   - 怎么保护：边框带常是扫描造成的亮度渐变，可能有几十像素宽，压在里面的手写字（如页边的档案编号）不随边框带一起抹掉；细暗线、长横线、贴着图片边缘被截断的残迹照常清除。

3. **页边的小黑点和杂笔迹（正文以外的噪点）**
   - 怎么找：先把一行行的字“糊”成条，圈出正文区域（比一个墨点还小的块不参与，免得页边成串的墨点被并进表格框、把正文区域撑到页边）。正文区域之外，如果有小团块的黑点，并且周围一片空白（没有别的字），就当噪点；紧贴图片边缘被截断的笔迹，多半是别的页透过来的，也一并去掉。
     - 页边常有一串挨在一起的墨点：只有字、线这样的“大墨迹”才说明附近是正文，成片的小墨点不能互相证明是文字（带颜色的除外，见下）；正文区域里的字（如表格框内紧挨边框的字）也不能证明区域外的墨点是正文。
     - 墨点外常有一圈浅灰的晕，只清深色核心会留下灰影：清除时连同浅色晕一起去掉（深色核心只有一两个像素、晕却是一小团实心的，也算墨点）；没有深色核心的浅灰小点，只要小、成团、附近没有大墨迹，也清掉，贴近页边的也一样（但只清实心的小团，不清细线笔画）。
     - 页边一横一竖拐角相接的灰色细线（扫描角标）整块清掉；单独的竖线（可能是手写的“1”）、三面四面有边的方框（装订孔）不动。
     - **页边的淡色痕迹**：背面透过来的字、纸张折角和折痕的阴影，只比纸色暗几个灰度，上面的阈值都抓不到。按局部纸色（大窗口中值）找出略暗的区域，只在正文区域之外、以及页边一圈（折角会从页角斜着伸进正文外框）里、远离正文行、附近没有真正墨迹（深色笔迹、不比墨点小的浅色笔画）、不带颜色的地方清除。
     - “被截断”要真的碰到图片边缘或第 1 步清掉的黑边；离边缘还有一段空白、字大小、笔画构成的块是页边完整的手写字（如页码、档案编号），保留。
   - 怎么保护：成串的文字、细长的手写笔画（比如页角手写的“1”）不会被当成噪点，因为文字周围总有别的字，笔画也不是小团块的形状。浅色印章、彩色笔迹的碎笔画（周围的浅色墨迹多半带颜色）不按“成片小墨点”放宽，也不向外扩清浅色晕；页边一圈的浅色笔画（装订孔轮廓等）不当浅灰小点清除。紧挨着字、落在同一行中段的短横和小点是标点（如页码“- 2 -”两侧的短横），保留。

   - **版心内的墨粉散点**（空白表格格子里成片的小黑点、背面印章透过来的碎点）：只清比墨点上限还小、在浅色阈值下仍是孤立小点的；半个字高以内有字、笔画、正文行，或碎块连成“像字的团”（够大，且墨迹较密或含细长笔画）的不动，所以小号标签、字旁的冒号顿号、断成点的淡字都保留。表格线、下划线这样的长直线不算“字”，但紧贴它的点和线本身都不动。

4. **正文淡字加深（墨粉不足的复印件，字只比纸色暗十几个灰度、笔画还被扫成断续的点）**
   - 怎么找字：不用固定的灰度阈值（淡字会被当成噪点），而是看“比周围暗多少”：用黑帽变换只量笔画尺度的暗度，比笔画宽得多的阴影、污渍、亮度渐变自然不计。再把“锐利的边缘”按一个字大小的窗口统计密度，连成一段段行；只有暗度够、边缘锐利（印出来的字边缘清楚，污渍、透字、阴影边缘发虚）、笔画不粗的段才算文字。确认的行沿行方向延伸到整个版心宽度，所以一行里中间整段淡到几乎看不见的字也能被找回来。
   - 怎么不加深噪点：行外的零星墨点、成片污渍一概不动；底色本身偏暗的地方（页边阴影、色块里的反白字）不动；和图片边缘连着的不动；印章保护区不动。
   - 怎么加深：按局部原始笔画峰值连续映射亮度，保留灰阶边缘，不再通过闭运算填粗笔画，也不把浅色边缘提前压成黑色。只往深里改，本来清楚的文字逐渐停止增强，未增强的像素原样保留。
   - **定向灰度恢复（默认）**：在原始笔画暗度上用 16 个方向的窄线核积累浅墨迹，扣除垂直于笔画方向的两侧背景，再按局部线响应归一化。这样不必先把弱墨迹二值化成骨架，连续但很浅的笔画也能参与恢复。空白位置须有沿线两侧的墨迹支持，避免向端点外拖出尾巴；孤立单点、印章保护区和行外不参与恢复。处理按文字行分块，保留灰阶边缘。
   - **骨架端点连接（可选）**：`--text-method endpoint` 使用上一版的 scikit-image Zhang 骨架提取和端点方向匹配，补连较少，适合更谨慎地处理短断口。`--no-interp` 同时关闭以上恢复，只保留像素加深。
   - 放在去噪之前做：去噪按加深后的完整的字确定版心和字高，正文行的笔画也不许去噪改动，所以淡字不会再被当成“页边淡色痕迹”或“孤立墨点”抹掉。去彩色噪点时，大片浅色彩色区域若多为成行的文字笔画（淡红头），也当文字保留。

**补回干净的样子**：标记出来的区域，用图像修补算法（Telea）从四周的纸张“长”出来填满，边缘做了柔和过渡，所以看不出补过的痕迹，也不会出现一块纯白色块。靠近标记区的文字笔画会先被“忽略”着参与计算，补完再原样放回，这样笔画的黑色不会晕染到补过的地方。

## 已知局限

- 版心内挤成一团、连成细长链的散点（如背面印章透过来的圆弧）和粘在表格线上的点，形状上和印得很淡的小字分不开，按“分不清就保留”不清除。
- 黑边只认厚实的色块或沿边缘延伸的长细线；伸到图片边缘的表格线、被边缘截断的字不再当黑边清掉。
- 假设页边最外约 4% 内没有真实内容；页边 3% 以内、版心之外的内容，若被图片边缘或黑边截断、或比字小、或是实心墨团，会被当作残留清除（完整的手写字保留）。
- 不接触图片边缘的黑色区域不会被识别为黑边。
- 正文区域外极淡（比纸色只暗几个灰度）、又不挨着其他笔迹的内容（如很淡的铅笔字）会被当成淡色痕迹清掉；背面透字只清正文区域外的部分，正文行之间的不动。
- 黑白扫描的骑缝章若外圈圆弧不在本页（只露出几个印文笔画，如 test/27.jpg 那种情况的黑白版），没有圆弧可拟合，仍可能被当成贴边笔迹清掉；彩色扫描时靠颜色可以保住。
- 笔画恢复依靠灰度证据与局部几何，无法识别字义；方向一致的真实空隙仍可能被误连。仅在短距离内恢复，长缺笔、急弯或没有足够残留墨迹的位置仍可能断续。可用 `--no-interp` 关闭插值和断笔修复。
- 淡字加深依赖“成行”：极淡又孤零零的一两个字（不在任何一行里）不会加深；墨粉缺失到连轮廓都没扫进来的笔画补不回来，只能加深残留的断点。
- 彩色噪点若和印章颜色相同、且印章正好压在噪点里（不再是独立的圆形区域），印章的浅色部分可能被一起清掉；紧贴线条、文字的深色噪点小点会保留。

## 断笔修复依赖与验证

通过 `uv sync` 安装依赖。可选旧版的骨架提取直接调用 [scikit-image skeletonize（Zhang 方法）](https://scikit-image.org/docs/stable/api/skimage.morphology/#skimage.morphology.skeletonize)，端点邻域搜索使用 SciPy `cKDTree`。骨架仅用于定位和估计方向，不把输出字体细化成单像素。

没有对整页做二值闭运算或通用图像填补：断口需要先判断笔画走向，整片填补容易把字间空白也补上。此方法不需要下载模型，不会用 OCR 结果替换原文。

运行回归检查：

```bash
uv run python -m unittest discover -s tests -v
```

检查覆盖横竖斜向短断笔、粗笔画宽度、平行笔画不粘连、第三条笔画交叉、长空白不臆造、完整线条与孤立点、保护区及空白页。

### 定向方案对比

新默认方案借鉴[脊线滤波](https://scikit-image.org/docs/0.25.x/auto_examples/edges/plot_ridge_filter.html)的沿线增强与法向背景抑制思路，用 OpenCV 实现定向匹配滤波，并加入双侧墨迹约束。也对比过 Sato 多尺度脊线滤波；当前样图中其断续现象更明显，未将它作为默认实现。

```bash
uv run python pic.py test2/0808.jpg                              # 新默认方案
uv run python pic.py test2/0808.jpg --text-method endpoint       # 旧版，输出会覆盖同名结果
```

新增回归覆盖弱墨迹文字人工断笔、孤立像素、纸面噪声、平行笔画、端点拖尾与保护区。固定的英文/数字人工断笔样例中，在同一深色判定阈值下，新方法恢复 181 个缺失像素，旧方法恢复 36 个，新方法在真值轮廓之外新增 8 个深色像素。这是合成样例的比较，不代表真实中文扫描件的恢复率；真实空隙仍可能被误连，彻底缺失的字形仍无法可靠重建。
